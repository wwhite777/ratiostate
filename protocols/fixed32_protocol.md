## Question and units

The evaluation asked whether normalizer-precision sensitivity observed on ten purposively selected development sequences persisted on an additional fixed set under the **same model and MNIST test dataset**. The primary descriptive paired score contrast was A11−A10, the effect of BF16 normalizer storage when the matrix is BF16. Ordinary FP16 was a required comparator. The development indices were 0, 1, 2, 3, 4, 7, 8, 11, 18 and 61, excluded from the new set. One 784-pixel image is the analysis unit; 783 predicted pixels are repeated positions, not independent images. The sample size 32 was an operational resource choice, not a power calculation. Original training overlap and near-duplicate status remain unknown.

The selected indices are the first 32 eligible test indices ranked by the binary SHA-256 digest of `RatioState-precision-extension-20260924-v1:index`, with index tie-break, after excluding the ten development indices. Labels, pixels and outcomes were not used in the ranking. Their exact order is in the selection and lock extracts. Byte-identical pixel duplicates within fixed32 and against development were to be retained and disclosed rather than replaced.

## Model, arms and order

The graph hash is `304f1905c945d25b4848873feaa3ea04c1fa6c84fa9230b214c24d2b85b1f83e` with TFJS 2.0 CPU execution. Start each image from zero states. Every arm uses the same 783 teacher-forced pixel calls, positions 0–782, inclusive FP32 state update/readout, original graph features and additive epsilon. Only the retained state fed to the next call is encoded. Later changed features and trajectories are part of the full-model intervention. The four crossed arms are A00 (matrix FP32, normalizer FP32), A10 (BF16, FP32), A01 (FP32, BF16), A11 (BF16, BF16); controls are `fp16_boundary` (FP16 both) and `bf16_pair_boundary` (two-word BF16 residual both). No arm measures physical deployment memory, throughput or energy.

For each image, A00 runs first because FP16 uses its same-image native reference. Rotate `[A10,A01,A11,fp16_boundary,bf16_pair_boundary]` left by the image ordinal modulo five. Each image starts independently; no recurrent state is shared. The original record allowed two concurrent whole-image workers, one numerical thread each, and specified 192 model and 192 score cells plus three development-image compatibility trajectories. Exact resource caps are in the lock extract; these are historical settings, not directions to rerun science.
